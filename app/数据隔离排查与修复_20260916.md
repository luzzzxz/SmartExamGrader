# 班级、测试、答案方案与透打隔离排查

2026-09-17 修订：本文中整卷答案签名冲突后的评分处理已被 [逐空评分修订与输出联动](评分修订与输出联动_20260917.md) 取代。跨测试隔离保留，正常单空更正不再使全卷成绩失效。

日期：2026-09-16。本次结论针对当前工作目录内的源码和数据库。

## 结论

确实存在多条可导致跨测试、跨答案方案混用的代码路径。问题不只在数据库查询：数据库结果已有 `session_id` 条件和 `(session_id, file_name)` 唯一约束，但界面共享状态、自动回填、模板文件、异步窗口、网页任务以及透打页序仍可能绕过这些隔离。本次已修改这些路径，并增加回归测试。

透打“印到另一张卷上”还可能由页序改变或中途跳页造成，即使数据库里的学生成绩本身没有串班，也会出现类似现象。代码问题可以确认；没有具体出错批次的原始纸张顺序，不能认定每次历史事故都由同一原因造成。

## 确认的问题与修复

| 范围 | 原行为及触发条件 | 修复后的行为 |
| --- | --- | --- |
| 历史测试加载 | 打开 B 测试时，缺失答案可能从 A 的 `fallback_answer_scheme_path` 补入；仅模板类型一致就可能被接受 | 删除跨测试补答案路径。缺失快照不再借用上一测试方案 |
| 共享答案方案 | 开始批改时重新读取共享方案文件，并覆盖当前测试快照；其他测试修改过共享方案时，历史测试会变 | 已绑定测试直接使用自身工作状态和快照；修改 OCR 规则及结构时自动保存到本测试，显式保存命名方案仍可更新共享方案 |
| 新文件夹与班级 | 新建测试保留上一个测试答案和结构；名册匹配失败时保留上一个班级 | 新文件夹清空旧答案、主观题配置；直批结构需明确设置或加载。不匹配的名册显示“未匹配”状态，不使用上班名单 |
| 多测试共用文件夹 | 文件夹匹配遇到多个测试时直接选最新；旧结果路径还可能把已有测试重新绑定到另一目录 | 多个直接绑定记录要求从“打开测试”明确选择；已有文件夹绑定的测试不能因单条旧结果被自动改绑 |
| 旧主观题成绩 | 自动合并旧 JSON，只核对扫描路径和题目编号，没有核对测试/答案/结构 | 自动合并要求测试 ID、模板、答案签名、结构签名一致；身份未知的旧文件不自动认领 |
| 换答案沿用分数 | “题目位置相同”就保留旧分数；保存时把旧分数重新盖上新答案签名 | 不兼容成绩不能直接改写签名。明确重新开始主观题评分时先备份原成绩，再建立新记录，禁止旧文件重新自动补入 |
| 正反面与横线配置 | 各测试共用 `direct_subjective_lines.json`；重建几何、保存单面时会读共享文件并保留其他试卷的另一面 | 横线配置按测试单独保存并纳入方案快照；保存选择题/页面元数据使用当前测试内存配置；恢复旧快照时不再用共享横线文件重建 |
| 模板图缺失 | 方案里的模板图丢失或复制失败后仍继续执行，实际可能使用上一试卷的模板图 | 明确报错停止恢复；不以其他试卷的残留图片代替。缺少直批结构的历史测试必须明确恢复结构后才能透打 |
| 窗口与异步任务 | 主观题/结构窗口持有旧数据，主界面却能切到另一测试；预览线程直接读取可变的当前模板和 Tk 变量 | 相关窗口存在时阻止切换上下文；关键保存先检查测试归属；模型回调检查原任务上下文；预览改用 Tk 主线程分步生成 |
| 批改过程中切换 | 批处理中的 `root.update()` 会处理新的切班、切测试点击，使一批处理中间改变归属 | 批处理中改为刷新界面绘制；不在处理中重新执行切换操作 |
| 保存与标注 | 只有当前目录绑定检查，未逐条核对结果原图及所属测试；改答案后可能拿旧成绩生成新标注 | 校验结果测试 ID、正反面图片父目录、是否混有多个班级；新结果记录答案/结构和原图版本签名，发现变化要求重批 |
| 透打页序 | 识别按自然顺序，历史加载按数据库文本顺序；例如 1、2、10 重开变为 1、10、2 | 历史加载及透打使用一致的自然顺序，再按原有倒序打印规则输出 |
| 透打缺页 | 找不到原图时先过滤掉；某一页渲染失败后跳过，后面的页会对应到错误纸张 | 缺图或部分缺背面时停止；任意渲染错误终止整批。正背面先在临时目录完成生成，再发布输出，渲染失败不会覆盖已有 PDF |
| 网页评分 | 自动寻找旧文件夹任务；相同图片路径/空位可能被认作同一试卷；重新上传会保留不适用的分数 | 任务 ID 包含测试及答案、结构、扫描文件版本；下载校验远端 manifest；不自动回退到旧文件夹任务 |
| 网页重新上传 | 服务端按学生路径和空位保留成绩，没有核对答案、满分或图片内容；旧浏览器仍能给新任务打分 | 服务端检查身份和上下文；保留成绩还需答案、满分、学生及图片内容相同；每次上传生成 revision，旧页面保存返回 409，要求刷新 |

主要修改文件：`enhanced_answer_card_gui_stats.py`、`core/db_session.py`、`core/pdf_overlay.py`、`core/web_sync.py`、`manual_grading_web_server.py`。

## 生效及使用变化

1. 下次启动本目录程序即使用修复后的本地代码；若程序仍开着，先保存工作再退出重开。
2. 新班级/新测试需明确加载对应答案方案或重新设置结构，不再默默沿用上一个测试。
3. 同目录有多个测试时，用“打开测试”选择具体记录。
4. 换答案/结构后重新批改再透打。缺原图时先恢复原图位置，不能靠跳过页面继续印。
5. 历史未知归属成绩、缺少结构的快照及旧网页任务不自动继承。原文件仍保留；应对照原卷或旧任务页面确认后恢复，不能通过猜测补入。
6. 网页服务端修复已写入本地 `manual_grading_web_server.py`，**本次没有部署或重启 VPS**。桌面新任务 ID 和下载校验在本地代码生效；服务端图片比对/revision 校验需要服务器更新该文件并重启后才生效。现有旧页面和旧任务应保留用于核对，不能声称已经迁移到新任务。
