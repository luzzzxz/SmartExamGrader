# 评分规则修订与输出联动

后续修订：自动重建输出已取消，当前按“成绩实时更新、用户主动导出时生成文件”运行。详见 [按需导出修复](按需导出修复_20260917.md)。下文的自动文件联动说明仅记录此前实现。

本次修复针对当前目录的程序源码。本文替代 9 月 16 日报告中“整卷答案签名不符即清空或阻止正常保存”的处理方式。

## 根因

此前把三种不同问题混在同一个整卷答案签名中处理：测试归属、试卷结构、评分规则修订。这个签名还包含答案方案名称、OCR 留白和置信度设置。更正一个空、修改识别设置，都可能导致整份成绩不兼容。

此外，单空重判先改配置，再提交旧版本成绩；批改窗口刷新又只更新分数、不更新外层版本。两者造成合法更正被拒绝。随后准备批改时返回空成绩，以及显式重判时删去所有空的评分字段，造成全卷评分丢失。这是先前隔离加固的设计错误，不是用户操作错误。

输出侧另有独立问题：预览缓存没有随成绩刷新；HTML 导出忽略成绩同步异常；网页课件用文件名区分，跨班同名文件有覆盖风险；Excel 上传失败曾被忽略。

## 新的处理方式

| 范围 | 处理 |
| --- | --- |
| 班级、测试、模板和原图归属 | 保留严格隔离，不能借一次保存更改成绩归属 |
| 试卷结构/裁图几何 | 结构不符时停止复用；保留原成绩，不清空 |
| 单空评分规则 | 成绩文件保存逐空规则快照，只标记受影响空的自动分待重判 |
| 其他空、教师人工分 | 不因某空改答案而丢失；覆盖目标空人工分仍需明确勾选 |
| 满分改变 | 该空的人工分也需复核，原评分保存在历史记录中，不静默截断 |
| 方案改名、留白、置信度等识别设置 | 不使既有评分失效 |

`core/grading_state.py` 实现逐空比较与评分状态迁移；打开、保存、重判、成绩汇总和网页打分包准备共用同一条迁移路径。迁移保留 OCR 原文、其他识别证据、旧评分历史和窗口持有的字典引用。

旧文件只有在原签名与当前配置吻合时，才自动补齐逐空规则。对于已经发生未知差异且没有逐空记录的旧文件，系统不能猜测哪些分数仍有效：保留文件及当前展示，提示恢复原版本或明确使用旧 OCR 重判。明确重判也保留人工评分，不再清空全卷。

## 更正一个空后的更新链

1. 核验当前测试和结构，保存原记录备份。
2. 修改当前测试答案快照，仅用已有识别文字重判目标空；其他空不改。
3. 保存评分记录及逐空规则版本。
4. 重算学生主观分、分项分、总分和百分制分数，写入测试数据库。
5. 刷新成绩汇总、分析和全班名次。透打和课件使用相同的并列排名规则（1、1、3）。
6. 通知已打开的整卡预览清除旧缓存；旧预加载任务通过代次检查失效。
7. 更新已登记输出；快速批改结束保存时也执行输出同步。

单空变化的影响范围与统计的影响范围不同：可以只重判一个空，但全班排序、平均分、正确率等必须重算。

## 文件和网页联动

`core/derived_results.py` 为每个测试保存输出登记，包括结果版本、路径、文件摘要和透打参数。已支持：

- 正/背面透打 PDF；
- 整卡标注 PDF；
- 老师讲评透打 PDF；
- HTML 讲评课件及配套 Excel；
- 已成功发布登记的网页课件，更新本地文件后再同步原服务器。

每个导出文件旁的 `.grading-source.json` 记录测试归属。自动更新必须同时满足归属和文件摘要检查，不能只凭同名文件或相同内容判断归属。另一测试占用相同路径后，即使字节碰巧一样，原测试也不能自动覆盖它。

生成 PDF/HTML/Excel 时先完成临时输出，再替换原文件；第二个文件替换失败会回退前面的文件。如果连回退都失败，保留原文件备份目录。生成中任何学生页面失败即停止整批，避免跳页错印。

网页上传文件名加入测试 ID 的稳定摘要，避免不同班级的同名课件互相覆盖。HTML 和 Excel 两次上传均检查返回结果。网页同步失败时保留本地新文件并记录待重试状态，不把成绩保存判为失败，也不宣称网页已经更新。这里没有在本次开发中连接真实 VPS 或上传学生数据。

### 使用边界

- 旧版导出的文件没有可靠归属登记，需要在新版中重新导出一次；之后纳入自动联动。不会遍历文件夹按相似文件名猜测并覆盖。
- 已打印纸张、另外复制的文件不能自动更新。正在浏览的 HTML 页面需刷新或重新打开。
- 新的测试专属网页文件名与旧版无测试标识的文件名不同；旧网页副本不会被误当作当前测试文件覆盖。
- 文件被外部修改、删除、占用，或服务器地址改变时，会报告对应输出待处理，保留成绩。网页同步失败也可在下次保存时重试。
- 数据库、多个本地文件和远程服务器不是一个跨系统原子事务；失败状态会分开报告，不能承诺在断电/断网时所有副本同时完成。

## 验证

运行：`py -3.14 -m unittest discover -s app/tests -q`。

114 项测试通过，覆盖：

- 更正单空、保留其他空及人工分、明确覆盖人工分、刷新旧窗口后关闭保存；
- 逐空规则迁移、重复保存不重复失效、改名/留白/置信度不误伤、满分变更保留证据；
- 未知旧版本保留显示和文件、跨测试/跨结构拒绝、同名扫描件与输出归属；
- 单空更正后真实临时 SQLite 数据库总分更新；
- 单空更正后名次、透打取值和课件统计一致，并重新生成临时 HTML、Excel、PDF 文件；
- 透打参数保留、其他 PDF 输出登记、输出只更新一次、并列排名一致；
- 输出冲突、生成失败和替换失败保留原文件；
- 网页课件跨测试命名隔离、Excel 上传失败、发布失败后的再次同步。
- 输出状态写入和预览刷新失败不会把已保存的成绩判为失败。

测试使用临时目录、临时数据库及模拟网络，不执行真实 OCR/大模型。PDF 测试验证导出流程和分值传递，不替代真实纸张上的打印校准。仍需在实际使用中确认设备打印效果。
